## Native differences and map direction

The native map screens are not identical. Android uses MapLibre and changes from regional to individual Crew markers at zoom `4.5`; its region detail includes active and inactive Crew counts. iOS uses Apple MapKit, changes levels at a longitude span of `45°`, draws custom pins, and includes Crew state in details. The current PWA uses MapLibre and combines searchable/detail fields from both clients. RICK's direction on the intended shared map baseline was requested but is still pending; because the native map providers and rendering differ, one PWA cannot be pixel-identical to both without a designated source of truth.

There is also a Home stats-copy difference: Android's screen uses shorter labels; iOS `SiteCatalog.Impact` uses more descriptive labels for the same figures. The PWA currently follows Android's visible Home text. For notifications, the PWA follows Android's silent first-sync behavior rather than iOS's first-sync behavior.

## Verification boundary

Static source review confirms the implemented routes, source data fields, valid empty map dataset handling, search/detail contracts, approved local Home imagery, notification limitations, complete first-sync baseline, and escaped calendar fields. The checked-in feed snapshot's image URLs use `images.squarespace-cdn.com`; MapLibre GL JS is locked at `6.16.0`. The native Android/iOS map JSON arrays were compared and are identical; the sync script also checks for future drift.

No local build/test has been run. No Android or iOS runtime screenshots have been compared against a PWA runtime capture, so 100% UI/UX parity is **not verified**. Required follow-up is RICK's map direction, a decision on cross-platform copy/sync differences, and runtime screenshot/flow comparison on both native clients and the installed PWA.
